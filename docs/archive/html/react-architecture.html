ReAct

Reasoning + Acting · arXiv 2210.03629 · Google / Princeton 2022

▌1. 动机：为什么要 ReAct？

❌ 纯推理（Chain-of-Thought）

# CoT: 只在脑子里推理
用户: 北京和上海哪个远？

Thought: 北京到上海约1200km...
         高铁约4.5小时...
Answer: 北京到上海距离...

LLM 凭训练数据推理
无法获取实时/外部信息
数据过时了就瞎编

❌ 纯行动（Tool-Use Only）

# Only Act: 调用工具但缺乏推理
用户: 帮我订去北京的票

Action: search_flights()
Observation: [国航CA1234...]
Action: book_ticket(...)  ← 没检查日期就直接订了！
Observation: 订票失败

工具调了一堆
但缺乏推理来决定"该调什么"和"结果什么意思"
容易瞎操作

ReAct 的核心理念：推理和行动交替进行，互相促进。
Thought 指导 Action 该调什么，Observation 反馈给 Thought 调整下一步。

▌2. 核心循环

# 每次 LLM 调用的输出格式
Thought: 我需要查询北京的实时天气数据，然后给出穿衣建议。
Action: get_weather("Beijing")

# 系统执行 Action，拿到结果后拼到对话里
Observation: {"temperature": 28, "condition": "sunny"}

# LLM 再次被调用（带上 Obs），输出下一步
Thought: 北京28度晴天，适合穿短袖。信息够了。
Answer: 北京今天28度，晴天，建议穿短袖出门。

▌3. 完整例子：多步推理+工具

问题：谁执导了《奥本海默》的导演所执导的最早电影？

经典 HotpotQA 风格——需要多跳推理

Thought 1: 我需要先找到《奥本海默》的导演是谁。

Action 1: Search["奥本海默 导演"]

Observation 1: 克里斯托弗·诺兰（Christopher Nolan）

Thought 2: 导演是克里斯托弗·诺兰。现在我需要找到诺兰执导的最早电影。

Action 2: Search["克里斯托弗·诺兰 最早的电影"]

Observation 2: 克里斯托弗·诺兰的第一部电影是《追随》（Following），1998年上映。

Thought 3: 诺兰最早执导的电影是《追随》（1998）。可以给出最终答案了。

Answer: 克里斯托弗·诺兰最早执导的电影是《追随》（Following），1998年上映。

关键：Thought 2 基于 Action 1 的结果（诺兰）决定下一步搜索方向。如果没有 Thought 环节，LLM 可能直接瞎猜诺兰最早的电影。

▌4. 论文中的重要发现

🔥 推理+行动协同

  • Thought 帮助 Action 不跑偏（推理指引行动方向）
  • Observation 帮助 Thought 修正（事实纠正推理错误）
  • 比纯 Chain-of-Thought 和纯 Tool-Use 都好

🔥 可解释性

  • Thought 是自然语言，人能看懂"它为什么这么干"
  • 出错了可以定位：是 Thought 推错了，还是 Action 调错了
  • 这被称为"白盒 Agent"的核心特性

🔥 应对幻觉

  • Action + Observation 让 LLM 基于事实行动
  • 而不是凭训练数据"背诵"答案
  • 尤其是需要实时数据、知识库查询的场景

🔥 行动空间任意

  • 论文里用了 Search / Lookup / Finish 三种 Action
  • 实际可以扩展为任意工具：API调用、数据库、计算器...
  • 通过 LLM 的 function calling 原生支持

▌5. 怎么实现一个 ReAct Agent

核心就是：在 system prompt 里告诉 LLM 输出格式 + 用 while 循环喂 Obs 回 LLM

# system prompt 关键部分
用以下格式回复：

Thought: 你当前的推理
Action: 工具名称(参数)
（或者如果已经足够了）
Answer: 你的最终答案

# Agent 循环伪代码
messages = [system_prompt, user_input]

while True:
    response = llm.chat(messages)
    
    if response 包含 "Action:":
        tool_name, args = parse_action(response)
        result = execute_tool(tool_name, args)

        messages.append(response)              # 加入 Action
        messages.append({"role": "user",        # 加入 Observation
                         "content": f"Observation: {result}"})
        # 继续循环，LLM 看到 Obs 后继续 Thought
    
    elif response 包含 "Answer:":
        return parse_answer(response)  # 结束

↑ 这就是 ReAct 的全部实现。不需要框架，一个 while 循环就够了。

▌6. ReAct vs Function Calling（Tool Calling）

LLM Function Calling

LLM API 原生特性。模型输出结构化的 tool_call 请求，由调用方执行。

{
  "tool_calls": [{
    "name": "get_weather",
    "args": {"city": "北京"}
  }]
}

这是底层能力，格式固定

ReAct

上面的架构模式。LLM 用自然语言输出 Thought + Action。

Thought: 天气会影响穿衣，先查天气
Action: get_weather("北京")

这是上层架构，格式灵活

现实中的融合：现代 Agent 框架通常把 ReAct 的 Thought 用 LLM 的 function calling 来实现——Thought 隐含在 LLM 内部，Action 通过 tool_calls 结构化输出。这就是你的实现做的事。
