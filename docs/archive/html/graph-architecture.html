Graph 架构 vs Pipeline 架构

两种 Agent 编排方式的对比 · 以 AniMate 角色扮演为例

▌Pipeline / Skill 架构

# Skill：一条直线，没有分支
for skill in skills:
    skill.run(ctx)

response = llm.chat(ctx.to_messages())
parse(response)

▌Graph 架构（LangGraph 风格）

# Graph：节点 + 条件边，可以循环/并行/分支
graph = Graph()
graph.add_node("analyze", analyze_emotion)
graph.add_node("retrieve", retrieve_knowledge)
graph.add_node("llm", call_llm)
graph.add_node("tools", execute_tools)

# 条件边：LLM 输出决定下一步
graph.add_conditional_edges("llm", router_fn, {
    "has_tools": "tools",   # 有 tool call → 执行工具
    "finished": END,           # 完成 → 输出
})

# 并行：情感分析和检索同时跑
graph.add_edge("entry", ["analyze", "retrieve"])

▌对比总结

Pipeline / Skill Graph
拓扑 直线，一根筋 DAG或带环图，可分支/并行/循环
状态 共享可变 Context 独立 State 对象，每个节点读写
执行控制 写死在代码里（for循环） 用条件边/路由函数动态决策
循环 手动写 while 循环（我们 tool calling 就这样） 条件边自循环，内置支持
可观测性 只能加日志自己看 LangSmith 等原生追踪每个节点
适合场景 固定流程，角色扮演，对话 复杂推理，多步决策，工具编排
