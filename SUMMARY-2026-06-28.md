## 3. Key Design Decisions with Rationale

### 3.1 ReactNode Streaming Coexistence

ReactNode retains direct `ctx` writes for `emotion`/`gesture`/`raw_text` during streaming (real-time UI updates). The diff returned is a **snapshot** of the final state after the ReAct loop completes. This avoids breaking the streaming pipeline while still enabling diff-based auditing.

**Rationale**: Removing streaming writes would require rewriting the entire streaming event pipeline — deferred to a future phase.

### 3.2 `_apply_diff` Refactored Branch Structure

```python
# Before (Phase 6.1):
if field in ("emotion", "gesture"):
    current = getattr(ctx, field, None)
    if current != value:
        setattr(ctx, field, value)
        # auto emit emotion.final / gesture.final

# After (Phase 6.2):
if field in ("emotion", "gesture"):
    setattr(ctx, field, value)  # no equality check, no auto-emit
else:
    current = getattr(ctx, field, None)
    if current != value:
        setattr(ctx, field, value)
```

**Rationale**:
- Removes dead `getattr` computation for emotion/gesture
- Emotion/gesture validated by AfterNode — engine doesn't need to gate on equality
- Prepares for future removal of ReactNode streaming ctx writes (diff becomes sole write path)

### 3.3 AfterNode Explicit Final Emit

AfterNode now explicitly emits `emotion.final` and `gesture.final` in both return branches:
- **Empty text branch**: `emit emotion.final(value="calm")`, `emit gesture.final(value=None)`
- **Normal branch**: `emit emotion.final(value=emotion)`, `emit gesture.final(value=gesture)`

**Rationale**: Timing is safe — emit happens inside `node.run()` (before NodeResult return), `_apply_diff` runs after return. No conflict.

### 3.4 ReactNode `next_node` Removal

Deleted redundant `next_node="after"` from both ReactNode return points. ReactNode → AfterNode is a direct edge; the engine ignores `NodeResult.next_node` for direct edges. Other already-migrated nodes (AfterNode, ReflectNode) also don't carry redundant `next_node`.

## 4. DiffHistory Rewrite: 4-Field Sync → 7-Field Async

### Phase 6.1 (Original)

- 4 fields: `trace_id`, `node_name`, `diff_json`, `created_at`
- Embedded inside `ChatLogDB` (`log_db.py`)
- Synchronous writes, no batching

### Phase 6.2 (Rewrite)

- **7 fields**: `trace_id`, `node_name`, `diff_json`, `inputs_json`, `events_json`, `duration_ms`, `created_at`
- **Standalone SQLite** at `anima/data/trace/diff_history.db` (independent from ChatLogDB)
- **Async with WAL mode**: `asyncio.Lock` serializes writes; WAL + `busy_timeout=5000` + `synchronous=NORMAL`
- **Buffered flush**: accumulates up to `max_buffer=100` records before batch `executemany` insert
- **Retention**: 30-day auto-cleanup via `cleanup()` method
- **Inputs capture**: `_capture_inputs()` in `GraphEngine` snapshots `node.reads` fields before execution
- **Duration tracking**: `time.monotonic()` delta in `_run_node` → `duration_ms` per node
- **Index**: `idx_diff_trace` on `trace_id`, `idx_diff_ts` on `created_at`

### New Fields Rationale

| Field | Purpose |
|-------|---------|
| `inputs_json` | What the node read (enables replay from inputs, not just outputs) |
| `events_json` | Events emitted during node execution (for debugging emit side-effects) |
| `duration_ms` | Performance profiling per node |
